# FairVote («Честный голос»)

Неофициальная платформа онлайн-голосования с максимальной проверяемостью и минимумом
хранимых персональных данных. Flask + SQLAlchemy + SQLite (WAL), целевой хостинг —
PythonAnywhere. UI на русском, код и комментарии на английском.

> **Статус: прототип для синтетических данных. Для реального политического
> голосования текущая схема защиты недостаточна.**
> Перед развёртыванием прочитайте [проверку безопасности от 26.10.2026](docs/security-review-2026-10-26.md):
> в ней разделены исправленные ошибки и оставшиеся ограничения протокола.
> Готовы: M0 (скелет, хранилища, крипто-примитивы), M1 (цепочка хэшей, контрольные
> точки, `verify.py`), M2 (реестр, «один человек — один аккаунт», вход, сессии, CSRF,
> rate limit в БД), M2.3 (TOTP и коды восстановления), M3 (опросы, контент,
> обязательства по допущенным), M4 (бюллетени: фиксированный формат, шифрование в
> браузере, вендоренный libsodium, батчи с корнем Меркла) и M6 (закрытие, публикация
> ключа, подсчёт, публичные артефакты, независимый пересчёт в `verify.py`),
> M5 (ручная верификация по одноразовому коду), M7 (админка без доступа к реестру),
> M8 (публичные страницы и i18n-каталог), M9 (`flask daily`: автостарт/автозакрытие,
> экспорт, шифрованные бэкапы, retention, удаление аккаунта), M10 (демо-сценарий
> федеральной кампании) и M11 (runbook).
> Восстановление доступа по коду, манифест статики (`/manifest.json`, хэш в
> `poll.start`), локальная проверка бюллетеня (`/verify`) и листаемый журнал.
> Секрет из кодового слова (Argon2id в браузере через libsodium sumo), паритет
> браузера и Python проверен байт в байт; редактор логов; подключаемый
> `VerificationProvider`. Проверки запускаются командой `python -m pytest`;
> успешные тесты не доказывают анонимность протокола. Сверка с ТЗ — в
> [docs/compliance.md](docs/compliance.md).

## Запуск

```bash
python -m venv .venv && . .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt -r requirements-dev.txt

export FV_DEMO_MODE=1
python -c "import base64,os;print(base64.b64encode(os.urandom(32)).decode())"
# четыре секрета по 32 байта base64: FV_SECRET_KEY, FV_MASTER_KEY,
# FV_VOTER_PEPPER_V1, FV_ED25519_SIGN_KEY
export FLASK_APP=fairvote:create_app
flask init-db && flask show-db
pytest
```

## Три вещи, которые надо прочитать в первую очередь

1. **Связи «человек ↔ ballot_id» в схеме нет вообще.** Решением D-2 таблицы `live_vote`
   и `superseded_ballot` удалены, переголосование отменено (`first_wins`): это отклонение
   от п. 5.3 ТЗ, цена — принуждённый голос неизменяем. Прямой ссылки на бюллетень в
   реестре нет, но сервер видит аккаунт и бюллетень в одном запросе; временная
   корреляция и наблюдение оператора остаются возможны. См. также проверку безопасности.
2. **Публикация приватного ключа после закрытия несовместима с receipt-freeness.**
   Любой, кто знает секрет, прочитает голос после публикации ключа. Смягчение — поле
   `key_publish_after` (отложенная публикация), предупреждения и k-порог. См. docs/05 D-4.
3. **Меркл-листья не публикуются, только корни.** Иначе `H(voter_key)` становится
   оракулом членства для любого, кто знает паспортные данные человека. См. docs/04 C1.

## Быстрая карта решений

| Решение | Почему |
|---------|--------|
| 4 SQLite-файла и 4 модуля доступа | разделение на уровне схемы; процесс приложения имеет доступ ко всем четырём |
| Серверные сессии в БД, rate limit в БД | несколько воркеров PA, нельзя хранить state в памяти |
| Свой `DBStorage` для Flask-Limiter | у `limits` нет SQLite-бэкенда, а memory запрещён |
| Бюллетень фиксированной длины | длина шифртекста не выдаёт «да/нет» и число выбранных пунктов |
| Публикация ящика только после закрытия | иначе появляется проверка голоса в процессе (покупка голосов) |
| Сессии/ключи/шифрование — только библиотеки | `argon2-cffi`, `PyNaCl`, `cryptography`, `pyotp`, `nh3` |
| Нет загрузки документов в MVP | меньше ПДн и меньше поверхности атаки; manual-провайдер — вне платформы |
| Строгий fail-closed | демо-провайдер в проде, отсутствие ключа, отсутствие issuer'а → отказ старта |

## Структура репозитория

```
fairvote/
  config.py            секреты из env, отказ старта без них
  db.py                четыре engine, PRAGMA, BEGIN IMMEDIATE
  ddl/sqlite/*.sql      схема четырёх хранилищ + триггеры
  security/            canonical JSON, crypto, password, totp, sessions, csrf, ratelimit
  registry/            идентичность и voter_key, аккаунты, округа, MFA, lockout
  polls/               контент, опросы, Меркл-обязательства по допущенным
  ballots/             формат бюллетеня, приём, батчи, очередь
  audit/               цепочка хэшей, контрольные точки, экспорт
  merkle.py            одно дерево для обязательств и батчей
  web/                 blueprints, формы, шаблоны, js и vendor (без CDN)
tests/                 pytest: функциональные проверки и регрессии
tools/check_docs_ddl.py  сверка DDL из проектных документов с SQLite
scripts/verify.py      независимая проверка журнала (stdlib + Ed25519)
docs/                  проект (01–05), журнал решений по модулям, runbook
```

## Лицензия и правовой статус

Проект не является системой ГАС «Выборы», не имеет юридической силы и не заменяет
установленную законом процедуру голосования. Политические взгляды — особая категория
персональных данных; перед реальной эксплуатацией требуется юридическая проверка
(см. docs/04 A18, Q14).
