## M8: страницы и локализация

| Файл | Роль |
|------|------|
| `fairvote/i18n.py` | каталог строк (ru), `t(key, **values)` |
| `fairvote/web/pages.py` + шаблоны | `/how-it-works`, `/privacy`, `/terms` |
| `templates/base.html` | навигация и футер целиком через каталог |

Обоснования:

1. **Ключи, а не русский текст.** `t("how.notrust.operator")` вместо готовой фразы:
   смена формулировки не ломает переводы, а тест сверяет, что все ключи из шаблонов
   есть в каталоге и ни одно значение не пустое.
2. **Страница «Как это устроено» — обязательная часть продукта, а не маркетинг.**
   Там прямым текстом: оператор может подменить JS; после публикации ключа знающий
   секрет прочитает голос; переголосования нет; хостинг видит IP; добавить или не
   записать бюллетень можно, и это обнаруживается, но не отменяется.
3. **Оператор обязан назвать себя.** В проде `Settings` не создастся без
   `FV_OPERATOR`, `FV_LEGAL_BASIS`, `FV_CONTACT`: политика конфиденциальности без
   оператора — не политика. В демо-режиме подставляются пометки о демо.
4. **Остальные шаблоны пока с русским текстом внутри.** Механизм готов (ключи,
   `t()`, контекст-процессор), миграция auth/admin-шаблонов — механическая работа;
   это записано как долг, а не выдано за сделанное.

## M9: эксплуатация и удаление аккаунта

| Файл | Роль |
|------|------|
| `fairvote/ops.py` | `start_due`, `close_due`, `flush_batches`, `export_public`, `purge_retention`, `housekeeping`, `backup_registry`, `run_daily` |
| `fairvote/web/account.py` | `/account`, `/account/delete` |
| CLI | `daily`, `backup-registry`, `purge-retention` |

Обоснования:

1. **Одна команда вместо пяти задач.** На free-tier хостинге планировщик даёт
   примерно одну задачу в сутки, поэтому `flask daily` делает всё: открывает
   опросы, у которых наступило время, сбрасывает пачки, закрывает истёкшие,
   публикует артефакты, снимает бэкап, чистит мусор и подписывает контрольную точку.
   Каждый шаг идемпотентен: запоздавший или повторный запуск не создаёт дублей.
2. **Бэкап реестра шифруется AES-256-GCM, ключ — вне платформы.** Если
   `FV_BACKUP_KEY` не задан, бэкап **пропускается** с записью в отчёте, а не
   пишется открытым. Восстановление проверяется тестом: расшифрованный файл
   начинается с `SQLite format 3`.
3. **Удаление аккаунта запрещено, пока опрос не закрыт и не истёк срок хранения.**
   Запись об участии — это и есть механизм «один человек — один голос». Разрешить
   удалять её сразу означало бы дать возможность проголосовать дважды: удалить
   аккаунт, зарегистрироваться заново с тем же `voter_key` и проголосовать ещё раз.
   Компромисс честно описан в интерфейсе и в политике: удаление доступно после
   `RETENTION_DAYS` — тогда данные и так подлежат удалению.
4. **Удаление подтверждается паролем** (и требует CSRF), каскадно удаляет сессии,
   коды восстановления и заявки; в журнал пишется только счётчик
   (`registry.purge`), без идентификаторов.
5. **Retention нуллит `voter_key`, не удаляя аккаунт.** Человек сохраняет вход и
   историю участия, но связь «один человек — один аккаунт» перестаёт проверяться —
   это и есть обещанное удаление идентифицирующих данных через N дней.
6. **Housekeeping** чистит: просроченные сессии, счётчики лимитов, просроченные
   коды верификации (со статусом `rejected`, `expired`) и брошенные строки очереди.
