# M0 — скелет, конфигурация, хранилища, крипто-примитивы

Статус: реализовано. Ссылки: [docs/02 §2.1–2.4](../02-architecture.md),
[docs/05 D-1…D-5](../05-decisions.md).

## Что входит в модуль

| Файл | Роль |
|------|------|
| `fairvote/config.py` | `Settings`: секреты только из env, отказ старта при отсутствии; запрет эфемерных ключей вне DEMO |
| `fairvote/db.py` | четыре независимых engine, PRAGMA на каждое соединение, `write_tx`/`read_tx`, применение DDL |
| `fairvote/ddl/sqlite/*.sql` | схема четырёх хранилищ (идемпотентные `CREATE ... IF NOT EXISTS`), триггеры |
| `fairvote/security/canonical.py` | канонический JSON для цепочки хэшей |
| `fairvote/security/crypto.py` | HKDF, AES-256-GCM, HMAC, sealed box, Ed25519 — обёртки над библиотеками |
| `fairvote/security/headers.py` | CSP без `unsafe-inline`, HSTS, nosniff, COOP/CORP, `no-store` |
| `fairvote/__init__.py` | фабрика приложения, `/healthz`, страницы ошибок без трейсбеков |
| `fairvote/cli.py` | `flask init-db`, `flask show-db` |

## Обоснования

### 1. Четыре engine вместо одного

`STORES = registry | polls | ballot_box | audit_log`, у каждого свой файл и своя
схема. Отдельные engine — это и есть техническая основа разделения: модуль ящика
физически не имеет объекта, через который можно прочитать реестр. Тест
`test_no_table_links_a_person_to_a_ballot` фиксирует главное обещание схемы.

### 2. `BEGIN IMMEDIATE` и `isolation_level = None`

На PythonAnywhere несколько воркеров пишут в один файл. Транзакция «прочитать и
затем записать» под `BEGIN` (deferred) может упасть с `SQLITE_BUSY` при апгрейде
блокировки. Поэтому DBAPI-соединение переводится в autocommit
(`isolation_level = None`), а `write_tx()` явно выдаёт `BEGIN IMMEDIATE` —
блокировка записи берётся сразу, конкуренты ждут на `busy_timeout=5000`.

Альтернатива (retry-loop вокруг `SQLITE_BUSY`) отклонена: она маскирует
взаимные блокировки и делает поведение зависимым от таймингов.

### 3. `NullPool`

Соединение не переиспользуется между запросами: в WAL-режиме новый читатель
всегда получает свежий снимок, а простаивающие соединения не держат блокировок.
При нашей нагрузке (десятки запросов в минуту) цена открытия SQLite-файла
несущественна, а предсказуемость важнее.

### 4. Канонический JSON — подмножество RFC 8785

Цепочка хэшей проверяется сторонним `verify.py`, поэтому представление записи
должно быть побайтово воспроизводимым. Мы ограничили формат тем, что реально
используется: строковые ключи, сортировка по code point, целые числа в пределах
±2^53, без float. **Float отвергается**: `json.dumps` для чисел зависит от
платформы, и верификатор унаследовал бы эту ошибку.

Тонкость: RFC 8785 сортирует ключи по UTF-16 code units, а `sorted()` в Python —
по code points. Для BMP-символов порядки совпадают; ключи наших записей —
ASCII. Ограничение зафиксировано в docstring модуля.

### 5. Формат AEAD-блоба

`b"FV1" || nonce(12) || ciphertext || tag(16)`, обязательный `aad`. Версия в
заголовке позволяет миграцию ключей/формата явно, а `aad` (например
`b"totp:<user_id>"`) не даёт переставить шифртексты между записями — именно это
делает дамп БД бесполезным без ключа и без контекста.

### 6. Секреты: fail-closed

`Settings.load()` требует `FV_SECRET_KEY`, `FV_MASTER_KEY`,
`FV_VOTER_PEPPER_V1`, `FV_ED25519_SIGN_KEY` (по 32 байта base64) и падает с
`ConfigError`, если чего-то нет. Никаких дефолтов вида `os.urandom()` в проде.
`Settings.for_tests()` создаёт эфемерные ключи, но `__post_init__` запрещает
`ephemeral_keys=True` при `demo_mode=False` — комбинация «демо-настройки в
проде» технически невозможна, а не «запрещена на словах».

### 7. Заголовки и страницы ошибок

CSP собирается из списка директив в одном месте и накрывает **все** ответы,
включая 404/413/429/500 (тест). HSTS выдаётся только при `request.is_secure`:
на PA TLS терминируется прокси, `wsgi.url_scheme` приходит корректным, а
доверять `X-Forwarded-Proto` от клиента нельзя.

Страницы ошибок не показывают трейсбек и содержат только `request_id`
(8 случайных байт), который не связан ни с IP, ни с путём.

### 8. DDL в `.sql`, а не в моделях

Схема — это контракт с проверяющим, её нужно читать глазами. Поэтому DDL лежит
в `fairvote/ddl/sqlite/*.sql`, применяется `flask init-db` идемпотентно, а тест
`test_packaged_ddl_executes` прогоняет каждый файл в чистой БД. Модели
SQLAlchemy (следующие этапы) будут отражать эту схему, а тест сверит колонки.

## Какие угрозы закрывает

| Угроза | Как |
|--------|-----|
| T2 (правка после старта) | триггер `poll_immutable_after_start` + тест |
| T4 (правка журнала) | триггеры `entry_no_update`/`entry_no_delete` + тест |
| T24 (подмена ящика) | `ballot_no_update`/`ballot_no_delete` |
| T16/T17 (XSS/инлайн) | CSP без `unsafe-inline`, автоэскейп Jinja2 |
| T20 (SQLi) | параметризованные запросы; схема отдельно от кода |
| T19 (частично) | выравнивание поведения: единая страница ошибки, без деталей |
| T21 (сессии, частично) | `__Host-` cookie, Secure/HttpOnly/SameSite=Strict в конфиге |
| N12 (зависимости) | только библиотеки; своих примитивов нет |

## Что осталось за рамками M0 (осознанно)

* Сессии в БД, CSRF, rate limit, lockout — M2.
* Аутентификация/TOTP/recovery — M2.
* Цепочка хэшей и `verify.py` — M1.
* Публичные страницы и i18n — M8.

## Как запустить

```bash
export FV_INSTANCE_DIR=$PWD/instance
export FV_SECRET_KEY=$(python -c "import base64,os;print(base64.b64encode(os.urandom(32)).decode())")
# ... то же для FV_MASTER_KEY, FV_VOTER_PEPPER_V1, FV_ED25519_SIGN_KEY
FLASK_APP=fairvote:create_app flask init-db
FLASK_APP=fairvote:create_app flask show-db
pytest
```
