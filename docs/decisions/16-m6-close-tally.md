## Обоснования

### 1. Порядок закрытия зафиксирован

`poll-close` → `poll.key_publish` → `poll.results`. Публикация ключа возможна только
из `closed` и только начиная с `max(closed_at, key_publish_after)` (D-4). Раньше —
`PollStateError`, позже — работает. Каждый шаг идемпотентен: повтор не создаёт
вторую запись в журнале (`has_entry`) и не переписывает ключ.

### 2. Ключ проверяется по обязательству

`publish_private_key` выводит публичный ключ из приватного и сравнивает
`blake2b-256` с `key_fingerprint`, зафиксированным **до старта**. Несовпадение —
отказ, а не «опубликуем что дали». Это закрывает T25: подменить ключ при закрытии
можно только вместе с публичным расхождением с журналом.

### 3. Привязка округа — на уровне подсчёта

Сервер записал `district_code` при приёме (из реестра, не из клиента). Талли
сверяет его с `district` внутри расшифрованного payload: расхождение —
`DISTRICT_MISMATCH`, бюллетень не учитывается. Так подмена округа клиентом
(docs/04 C5) не проходит, причём проверка воспроизводима любым.

### 4. Порог k защищает разбивку, а не сумму

Округ с числом бюллетеней меньше `k` не публикует разбивку, но его бюллетени
входят в общенациональные суммы: иначе голоса малых округов исчезали бы из итога.
Это записано и в коде, и в шаблоне страницы результатов.

### 5. Бюллетени публикуются только после закрытия

`/transparency/export/<poll>/ballots.jsonl` отдаёт `404`, пока идёт голосование:
иначе появляется проверка «мой голос в ящике» и вместе с ней рынок проверяемых
голосов (docs/01 T8). Это же правило действует для подписи.

### 6. `verify.py` теперь действительно независимый

Скрипт проверяет: цепочку, подписи файлов, **корни Меркла батчей**, отпечаток
ключа против обязательства, расшифровку каждого шифртекста (PyNaCl), размер
открытого текста, `poll`/`district` внутри payload, допустимость каждого выбора,
порог k — и пересчитывает итоги. Всё, что ему нужно, — четыре файла и
опубликованный ключ.

Он **не** импортирует наш пакет: логика подсчёта продублирована сознательно, как и
канонический JSON, иначе аудитор доверял бы тому же коду, который проверяет.
Тест `test_verify_py_recounts_the_poll` прогоняет полный цикл: голоса → закрытие →
ключ → выгрузка → `verify.py` → `RESULT: OK, valid=3`.

### 7. Две проверки, которые ловят реальные подмены

* `test_verify_py_detects_a_tampered_ballot` меняет округ в строке ящика →
  `DISTRICT_MISMATCH`, код выхода 1.
* `test_verify_py_rejects_a_substituted_key` подменяет приватный ключ в `key.json` →
  `KEY_MISMATCH`: пересчёт «новым» ключом не сойдётся с обязательством.
