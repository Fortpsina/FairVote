# M5 + M7 — ручная верификация по коду и админка

Статус: реализовано. Ссылки: [docs/05 D-3](../05-decisions.md),
[docs/02 §2.5.1, §2.7](../02-architecture.md), [docs/01 T3](../01-threat-model.md).

## M5: верификация без документов

| Файл | Роль |
|------|------|
| `fairvote/registry/verification.py` | одноразовый код, поиск, решение, истечение |
| `fairvote/web/verification.py` + шаблон | заявка, показ кода один раз, статус |
| CLI | `verification-decide`, `verification-pending` |

Обоснования:

1. **Код хранится как Argon2id-хэш, а поиск идёт перебором ожидающих заявок.**
   40-битный код нельзя хранить открытым: утечка БД дала бы список «кто ещё не
   проверен». Ожидающих заявок мало, веб-эндпоинт ограничен 5 в сутки, CLI — локальный.
2. **Одноразовость через `UPDATE ... WHERE decision IS NULL`.** Два оператора,
   обработавшие один код одновременно, не создадут два решения: второй получит
   «заявка уже обработана» (проверяется `rowcount`).
3. **Статусы**: `registered → proof_submitted → verified | rejected`. Отклонённый
   может подать заново, но не больше `MAX_REQUESTS_PER_USER` раз; код живёт 14 дней,
   просроченные закрываются `expire_requests`.
4. **Демо-провайдер запрещён вне `DEMO_MODE`** — проверка в обработчике, а не только
   в конфиге.
5. **Никаких файлов.** В БД остаются метод, дата, код причины и округ; сам документ
   платформа не видит.

## M7: админка

| Файл | Роль |
|------|------|
| `fairvote/web/admin.py` | список, создание, правка, пункты, варианты, округа, ключ, закрытие, публикация ключа, пересчёт |
| `fairvote/polls/catalogue.py` + `fairvote/data/districts.json` | публичный справочник округов |
| `admin_action` | быстрый журнал действий админа (истина — audit_log) |

Обоснования:

1. **Граница «админ не видит реестр» — структурная.** `web/admin.py` не импортирует
   `fairvote.registry` вообще; тест проверяет это по списку импортов. Выбор округа
   идёт из **публичного справочника** `fairvote/data/districts.json`, а не из таблицы
   `district`: справочник — это публичные названия и коды, реестр — люди.
2. **TOTP обязателен, и это не пожелание.** `_start_session` выдаёт уровень `admin`
   только при `role == 'admin'` **и** подтверждённом TOTP. Без второго фактора сессия
   `full`, а админский blueprint отправляет на настройку TOTP. Понижения до
   «пароль-только» не происходит.
3. **Старт опроса — системная операция, не кнопка.** `commit_start` читает реестр для
   снапшота, поэтому он вызывается из CLI (`flask poll-start`), а не из веб-формы:
   так админ физически не инициирует чтение реестра.
4. **Правки только до старта.** Служба бросает `PollLocked`, триггер БД страхует,
   публичный `content_hash` в журнале делает правку после старта обнаружимой.
5. **Каждое действие — запись в журнал.** Сервисный слой пишет `poll.create`,
   `poll.update`, `contest`/`option`/`district` (в составе `poll.update`), `poll.key_commit`,
   `poll.close`, `poll.key_publish`, `poll.results`; таблица `admin_action` даёт
   быстрый список «кто что делал».
6. **Публикация ключа — единственное место, где приватный ключ попадает на сервер**,
   и только после закрытия и не раньше `key_publish_after`; отпечаток сверяется с
   обязательством.
