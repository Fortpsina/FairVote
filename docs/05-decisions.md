изменения проекта. Этот файл — **источник истины** при расхождении с docs/01–04.

## D-1. libsodium.js вендорится (решено)

`static/vendor/libsodium.js` + `libsodium-wrappers.js` — **сборка sumo**
(`libsodium-sumo` 0.7.15 и `libsodium-wrappers-sumo` 0.7.15). Sumo выбран, потому что
стандартная сборка не содержит `crypto_pwhash`, а он нужен для опционального вывода
секрета из кодового слова (Argon2id в браузере). Цена — примерно +300 КБ.

SHA-256 обоих файлов в `vendor.lock`, лицензии рядом, хэши входят в `manifest.json`
и в запись `poll.start`. Воспроизводится командой
`python tools/vendor_libsodium.py --update`, проверяется `--verify` и тестами,
которые запускают сборку в Node: `crypto_box_seal` (round-trip) и `crypto_pwhash`
(паритет с `argon2` в Python — байт в байт).

Почему без вариантов: `crypto_box_seal` — это X25519 + XSalsa20-Poly1305; WebCrypto
XSalsa20 не умеет, свой JS-крипто писать запрещено. Никаких CDN: файл отдаётся с нашего
домена. Если понадобится «ноль стороннего кода», единственная замена — нативный клиент
или расширение браузера (вне MVP).

## D-2. Переголосования нет; связи «человек ↔ ballot_id» нет вообще (решено)

Заказчик выбрал `first_wins` без `live_vote`. Это **отклонение от п. 5.3 ТЗ**
(«до закрытия может переголосовать»). Фиксирую последствия честно:

| Что | Было (проект 1.0) | Стало (2.0) |
|-----|-------------------|-------------|
| `live_vote` (связь user ↔ ballot_id) | была, шифрованная, удалялась при закрытии | **удалена из схемы** |
| `superseded_ballot` | был | **удалён** |
| `k_linkage_vN` | был | **не нужен** |
| Повторная отправка | переголосование | `409`, голос не меняется |
| `revote_policy` | `last_wins`/`first_wins` | только `first_wins` (иначе отказ старта) |
| Принуждение (T7) | смягчалось переголосованием | **не смягчается**; остаётся предупреждение и k-порог |
| Анонимность в MVP | политика + временная связь | **нет постоянной связи вообще**; деанонимизация возможна только через логи хостинга/IP |

**Почему это не бесплатно.** Переголосование — единственная дешёвая защита от
принуждения: «проголосуй за X» можно было обесценить, переголосовав позже. Теперь
принуждённый голос неизменяем. Поэтому:
1. перед отправкой бюллетеня — отдельный экран-предупреждение («изменить голос будет
   нельзя; если на вас давят — не голосуйте с этого устройства») с явным подтверждением;
2. в `/how-it-works` и в модели угроз это записано как нерешённое свойство;
3. если позже понадобится вернуть переголосование, минимальный путь — вернуть
   `live_vote` (см. docs/02 §2.4.9 старой редакции, D-2-b): +таблица, +шифрование,
   +удаление при закрытии, +2 теста. Решение обратимо, но требует вашего согласия.

**D-2-b (на случай смены решения).** Единственный способ разрешить переголосование без
связи — отказаться от «одного бюллетеня на человека» и считать по правилу «последний на
`ballot_id`». Тогда любой, кто знает чужой `ballot_id`, может перебить чужой голос.
Мы этот вариант **не выбираем**: молчаливая подмена хуже, чем отсутствие переголосования.

## D-3. Файлы-доказательства не принимаются (решено)

`proof_document`, `security/uploads.py`, Pillow, `var/proofs/`, перекодирование, TTL
удаления — **не реализуются**. Причина: это единственный компонент, где малое
преимущество в UX оплачивается хранением самых чувствительных ПДн и парсером
недоверенных файлов.

Как работает верификация вместо этого:

```
избиратель                    провайдер (вне платформы)          FairVote
    │  подаёт заявку ─────────────────────────────────────────────▶ verification_request
    │  получает одноразовый КОД (8 символов, показывается один раз) │  (user_id, код-хэш, метод)
    │  передаёт документ и КОД провайдеру по его каналу ──────────▶ │
    │                                                              │  оператор провайдера:
    │                                                              │  flask verification-decide <код> --approve
    │  видит статус verified ────────────────────────────────────────│  (запись решения, без ПДн)
```

* В FairVote попадают: одноразовый код (только хэш), метод, дата решения, округ, код
  причины. Ни ФИО, ни скана, ни адреса.
* Код одноразовый, живёт до решения, при отказе аннулируется; перебор ограничен
  (8 символов из 32-буквенного алфавита = 40 бит, лимит 5 попыток/час на код).
* Оператор провайдера не получает доступа к аккаунту, только право внести решение по коду.
* `VerificationProvider` остаётся интерфейсом: `DemoProvider` (мгновенно, только
  `DEMO_MODE`) и `ManualProvider` (код + CLI). IdP/ЭП подключаются позже без изменения схемы.

## D-4. Публикация приватного ключа — флаг на опрос, по умолчанию «сразу» (решено)

Поле `poll.key_publish_after` (UTC, NULL = сразу при закрытии). Семантика:

* `NULL` (по умолчанию) — ключ публикуется сразу после закрытия, итоги доступны сразу;
* дата в будущем — окно «отложенной публикации»: после закрытия ящик уже опубликован,
  но итоги и ключ скрыты до `key_publish_after`. Смысл: принуждающий не может проверить
  голос сразу после закрытия; интерес к давлению обычно падает. Проверяемость не
  теряется — публикация откладывается, а не отменяется.
* Админ **не может** опубликовать ключ раньше `key_publish_after` (`409`); попытка —
  в журнале. Обойти это он может только вне платформы (публикация ключа в своём канале),
  что видно по расхождению с журналом.
* `key_publish_after` входит в неизменяемые поля (правка после старта запрещена).

Почему не «пороговое дешифрование»: оно бы уничтожило главную функцию — независимый
пересчёт любым желающим. Отложенная публикация оставляет обе функции.

## Что меняется в схеме (дельта к docs/02)

### registry.sqlite

```sql
-- ДОБАВЛЕНО в M2: роль администратора (иначе привилегия определялась бы по логину)
-- app_user.role TEXT NOT NULL DEFAULT 'voter' CHECK (role IN ('voter','admin'))

-- УДАЛЕНО: live_vote, superseded_ballot, proof_document
-- ДОБАВЛЕНО:
CREATE TABLE verification_request (
  id           INTEGER PRIMARY KEY,
  user_id      INTEGER NOT NULL REFERENCES app_user(id) ON DELETE CASCADE,
  method       TEXT NOT NULL CHECK (method IN ('demo','manual','idp','esign')),
  code_hash    BLOB NOT NULL UNIQUE,      -- SHA-256(код), код показывается один раз
  code_attempts INTEGER NOT NULL DEFAULT 0,
  created_at   TEXT NOT NULL,
  expires_at   TEXT NOT NULL,             -- 14 дней
  decided_at   TEXT,
  decision     TEXT CHECK (decision IN ('approved','rejected')),
  reason_code  TEXT,
  decided_by   TEXT                       -- 'demo' | 'manual:<провайдер>', без ПДн
);
CREATE INDEX ix_vreq_user ON verification_request(user_id, created_at);
```

`participation` остаётся единственным следом участия: `(poll_id, user_id, voted_on)`.

### polls.sqlite

```sql
-- poll.revote_policy: CHECK (revote_policy IN ('first_wins'))  -- иначе отказ старта
-- poll: ДОБАВЛЕНО
--   key_publish_after TEXT,   -- NULL = сразу при закрытии (D-4)
```

### ballot_box.sqlite

```sql
CREATE TABLE ballot_queue (
  id            INTEGER PRIMARY KEY,
  poll_id       TEXT NOT NULL,
  ballot_id     TEXT NOT NULL,            -- публичный псевдоним, 64 hex
  district_code TEXT NOT NULL,            -- server-authoritative, из реестра
  client_nonce  BLOB NOT NULL,
  ciphertext    BLOB NOT NULL,
  received_slot TEXT NOT NULL,
  confirmed     INTEGER NOT NULL DEFAULT 0,
  created_at    TEXT NOT NULL,
  UNIQUE (poll_id, client_nonce),
  UNIQUE (poll_id, ballot_id)             -- второй бюллетень невозможен (D-2)
);

CREATE TABLE ballot (
  seq           INTEGER PRIMARY KEY AUTOINCREMENT,
  poll_id       TEXT NOT NULL,
  ballot_id     TEXT NOT NULL,
  district_code TEXT NOT NULL,
  ciphertext    BLOB NOT NULL,
  slot          TEXT NOT NULL,
  batch_id      INTEGER NOT NULL,
  UNIQUE (poll_id, ballot_id)
);
```

`ballot_id` в ящике — **не** связь с человеком: он не хранится в реестре, не связан с
`user_id` и нужен ровно для того, чтобы избиратель нашёл свой бюллетень по секрету.

## Что меняется в поведении

1. `POST /vote/<poll>` второй раз → `409` (без указания причины), голос не меняется.
2. `POST /vote/<poll>` с уже существующим `ballot_id` → `409` (защита от «перехвата»
   чужого псевдонима: лучше явная ошибка, чем молчаливая потеря голоса).
3. `GET /vote/<poll>` показывает предупреждение о необратимости + подтверждение.
4. Закрытие: нет чтения `live_vote`, нет списка `superseded`; публикуется ящик
   (`ballot_id`, `district_code`, `slot`, `ct`) + `poll.close`.
5. Итоги: `GET /polls/<slug>/results` отдаёт 404/заглушку до `max(closed_at, key_publish_after)`.
6. `scripts/verify.py`: не применяет `superseded`; правило — «один `ballot_id` = один
   голос» (дубликат = аномалия `DUPLICATE_BALLOT`); проверяет `district_code` из ящика
   против `district` в расшифрованном payload.
